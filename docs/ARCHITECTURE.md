# 产品技术方案与数据契约

日期：2026-10-28。T010 已完成，本方案作为 T020 实施基线；依赖版本与兼容能力尚待验证。

## 已确认的选择原则

产品质量优先于教学便利和尽快跑通。选择有维护、文档、适配能力和验证路径的成熟方案；学习围绕真实产品实现展开。分阶段交付缩小每次功能范围，已交付能力应满足相应的数据正确性、可靠性和体验要求。

已确认首版包含淘宝、京东、不限品类、网页、Chrome 与 Edge 扩展、链接比较及跨品牌替代搜索。React + TypeScript、WXT、FastAPI 与 SQLite 作为 T020 工作基线；具体依赖版本、模型协议、采集可行性和部署连接仍需实测。

原先“原生网页、T020 只存内存、T060 才做持久化”的建议已被本方案取代。以下组合供 T020 实施；技术验证结果仍需据实记录。

## 1. 推荐技术组合

| 部分 | 推荐 | 对应的产品要求与边界 |
| --- | --- | --- |
| 网页 | React + TypeScript + Vite；React Router 管理路由，TanStack Query 管理后台数据 | 支持商品比较、需求编辑、任务进度、证据查看和历史记录；统一处理缓存更新、加载、错误与任务切换。服务端是事实来源，查询缓存不替代数据库 |
| UI | Ant Design 基础组件，配合项目自己的页面设计与主题 | 复用表单、表格、弹层和校验能力；围绕商品卡片、可读的参数比较和证据抽屉设计，做响应式、键盘操作和状态反馈检查。组件库本身不能证明体验优秀 |
| 扩展 | WXT + React + TypeScript，Manifest V3 | 复用构建、入口与浏览器适配能力；Chrome、Edge 分别加载验收。网页与扩展共享接口类型及适合复用的展示组件；商品页采集脚本保持轻量 |
| API 与业务 | Python + FastAPI + Pydantic | 按任务、采集、价格、证据和 Agent 划分模块；校验输入与模型结果，通过 OpenAPI 生成/校验共享 TypeScript 契约；不重复手写两套易漂移字段 |
| 数据 | T020 起使用 SQLite + SQLAlchemy + Alembic | 任务、商品条目和操作状态落盘；T030 起保存不可变采集快照及证据。使用迁移、事务和唯一约束，建立备份与恢复方式。内存只承担缓存 |
| 采集与搜索执行 | 扩展读取用户授权的当前页面；Playwright 驱动独立浏览器会话；淘宝、京东分别适配 | 保存所选 SKU、价格条件、参数和详情图覆盖。登录与人工验证允许用户接管；官方接口仅在权限、覆盖和价格语义验证后使用 |
| Agent 编排 | 优先评估 LangGraph 的状态图、检查点与人工介入能力 | 对应条件补查、暂停、继续、错误恢复和停止条件；商品判断、硬条件核实、价格计算仍由项目明确实现。采用单 Agent 配合受控工具，按实际任务需求决定后续拆分 |
| 模型接入 | 真实渠道适配器 + 对应维护中的 SDK | 先验证实际 Gemini 渠道的协议与能力，再决定 SDK；不能把官方能力直接视为用户渠道能力。模型密钥只在后台 |
| 验证 | Python 局部/API/数据库检查，前端类型与组件检查，Playwright 端到端和真实页面样本 | 按风险从对应功能阶段开始，T060 汇总回归评估；不等全部业务完成后才检验数据、恢复和边界 |

版本选择依据维护状态、平台兼容、依赖约束和实际验证，在 T020 锁定；不为追逐最新主版本牺牲稳定性。

## 2. React 与 Vue 的取舍

Vue 3 + TypeScript 同样可以满足产品要求；这里推荐 React，依据是本项目需要统一网页与扩展 UI、成熟的数据请求层、组件组合和丰富的交互工作台，而所推荐的 React、TanStack Query、Ant Design、WXT 组合能明确覆盖这些职责。此结论是项目适配判断，不是 React 在性能、质量或求职价值上普遍优于 Vue 的断言。

React 官方建议评估成熟框架，并说明 Vite 只提供构建基础。本项目定位为本地交互应用、业务服务由 Python 提供，因此建议采用 Vite SPA，配合既有路由和服务端数据管理方案；路由、请求、错误边界和状态同步都有明确实现归属，不仅安装 React 就视为架构完成。网页生产构建可由 FastAPI 提供，开发期前端开发服务代理 API；扩展使用可配置的后台地址。

## 3. 数据与任务可靠性

SQLite 适合当前单用户、本地运行的部署目标。数据库放在服务所在系统的本地数据目录，由服务访问；不让 Windows 与 WSL 跨文件共享直接并发操作同一个数据库。连接、事务、写入并发、备份和迁移需验证。未来出现多实例或持续高写入并发需求时评估 PostgreSQL；ORM 不代表无需验证就能迁移。

T020 就保存任务和商品输入，刷新及服务重启后可以读取；T030 保存采集快照、证据索引和图片文件引用。修改所选规格或重新采集生成新版本，已有结论引用对应版本，防止价格和参数更新后结论错配。图片及会话文件存私有运行目录，用户输入数据不作为公开样例提交。

T040/T050 引入 Agent 时同时接入持久化检查点。LangGraph 检查点用于恢复图状态，并不自动等同于后台调度、外部动作恰好执行一次或结果正确。API 接收任务后交给有生命周期管理的执行器；执行前后保存运行状态，持久化工具结果，按任务/步骤使用幂等标识、有限重试、超时与取消。重启后识别中断任务并显式恢复或请求用户继续，不能悄悄把已失败的操作显示为成功。检查点后端、运行器和模型适配在 T010 设计验证方法，在获授权的 T020 技术探针中检验并确定。

首版先验证单机执行需求；消息中间件、分布式调度或更多服务根据真实并发、可靠性和部署需求引入。每项基础设施须有明确职责和验收方法。

## 4. 提前验证核心风险

后续获得对应实施授权后，T020 建设基础流程的同时，用小规模技术探针检查：

- Windows Chrome、Edge 到 WSL API 的连接，扩展权限、配对和来源限制；文件可见不等于服务可达。
- 淘宝、京东代表性真实页面的所选规格、参数、价格条件和详情图访问路径；记录登录、验证与缺失内容，形成采集适配可行性结论。
- 私有配置就绪后验证 Gemini 渠道的文本、图片、结构化输出、工具调用、错误与用量返回；SDK 与编排器的适配边界据此确定。
- LangGraph 检查点后端与实际调用适配器的最小暂停/恢复行为；工具重放不能引入重复写入。

探针用于尽早暴露架构风险，不视为完整采集、分析或 Agent 功能交付；不等到 T040/T050 才首次验证核心前提。当前文档阶段未做模型、平台页面或服务探针。

## 5. 商品读取与证据

扩展负责用户当前登录页面的主动提交及采集预览；Playwright 用于有权限的搜索、候选打开与核实。Windows 浏览器与 WSL 自动化浏览器是不同会话；复用认证状态、远程连接或浏览器运行位置须单独确认和测试，不假定共享登录。Cookie 和浏览器状态不进入仓库或公开日志。

各平台适配器提供页面读取、规格识别、参数提取、图片覆盖和失败分类；单位归一与金额计算为确定性代码。模型处理图片及解释差异时必须引用证据，不能把视觉推断作为已确认参数。页面状态、已选 SKU 与采集时间作为同一次快照保存。搜索结果只提供线索，候选详情和硬条件必须核实。

页面内容、搜索结果及图片均为不可信资料。后台校验工具名、参数和允许访问的目的地；不执行页面中的指令。身份、规格、价格或关键硬条件无法确认时，允许补查和人工介入，并明确说明结论的覆盖范围。

## 6. 最小数据契约

| 对象 | 逻辑字段及约束 | 首次落地 |
| --- | --- | --- |
| Task / TaskEvent | task_id、状态、版本、时间、错误、事件；网页与扩展共享；状态变化可重读 | T020 |
| ItemInput | item_id、原始 URL、平台、入口、浏览器、标题、幂等标识；保留规格相关查询参数 | T020 |
| CaptureSnapshot | snapshot_id、商品身份、店铺、所选规格、时间与覆盖情况；更新生成新版本 | T030 |
| Attribute / PriceOffer | 参数值、单位、语义与证据；价格、数量、运费、地区和优惠条件；金额精确表示 | T030/T040 |
| Evidence | evidence_id、快照、来源、原文/图片位置、时间、来源类型与完整性 | T030 |
| UserNeed | 用途、商品预算、硬条件及偏好；条件有版本，修改后旧结论需重新评估 | T040/T050 |
| Comparison / Candidate | 关联快照、核实状态、差异、未知项、证据和实际搜索范围 | T040/T050 |
| AgentRun / ToolCall | 运行与检查点关联、工具参数和实际结果、耗时、错误与用量；敏感信息脱敏 | T040/T050 |

未知区分未采集、未提供、冲突和不适用。重复请求使用幂等标识控制；相同 URL 不代表相同 SKU，重复输入不能覆盖不同采集快照。类型检查与 JSON Schema 合法不证明商品事实真实，仍需字段校验和来源核对。

## 7. 首个产品流程与质量条件

T020 按推荐结构建立 React 网页、WXT 扩展、FastAPI API、数据库和迁移。网页创建任务并添加链接，扩展选择同一任务提交当前页；两入口读取相同任务，正确显示“已加入，待采集，未分析”。仅登记链接阶段不伪造商品分析。

T020 检查正常提交、重复请求、非法 URL、任务不存在、后台中断、刷新与服务重启；数据库记录不能丢失。Chrome、Edge 分别验证；页面有清楚的加载、成功、失败和重试反馈。质量验收与学习掌握分别记录。

T030 起使用人工核对过的真实商品样本，覆盖不同 SKU、优惠门槛、缺失参数和未加载图片。T040/T050 起检查证据引用、硬条件满足情况、错误恢复、暂停/继续、循环停止和确实有/无合格候选的路径。T060 汇总固定案例、性能与回归结果；任何比例和性能主张都需样本与真实测量。

## 8. 学习安排与待验证事项

每个功能仍解释数据流、关键实现和成熟组件的边界，安排一个修改练习与失败案例。教学不决定框架降级，不以学习者尚未掌握为由把已完成产品功能记为未实现；功能完成、体验、学习和跨平台结果分别记录。

依赖版本、Gemini 渠道配置、平台采集覆盖、检查点与执行器适配、扩展配对细节和真实连通性仍待验证。业务实现、安装依赖、收费接入、部署和 Git 交付按实际授权执行；本轮只更新方案。
