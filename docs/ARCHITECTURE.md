## 2. React 与 Vue 的取舍

Vue 3 + TypeScript 同样可以满足产品要求；这里推荐 React，依据是本项目需要统一网页与扩展 UI、成熟的数据请求层、组件组合和丰富的交互工作台，而所推荐的 React、TanStack Query、Ant Design、WXT 组合能明确覆盖这些职责。此结论是项目适配判断，不是 React 在性能、质量或求职价值上普遍优于 Vue 的断言。

React 官方建议评估成熟框架，并说明 Vite 只提供构建基础。本项目定位为本地交互应用、业务服务由 Python 提供，因此建议采用 Vite SPA，配合既有路由和服务端数据管理方案；路由、请求、错误边界和状态同步都有明确实现归属，不仅安装 React 就视为架构完成。网页生产构建可由 FastAPI 提供，开发期前端开发服务代理 API；扩展使用可配置的后台地址。

## 3. 数据与任务可靠性

SQLite 适合当前单用户、本地运行的部署目标。数据库放在服务所在系统的本地数据目录，由服务访问；不让 Windows 与 WSL 跨文件共享直接并发操作同一个数据库。连接、事务、写入并发、备份和迁移需验证。未来出现多实例或持续高写入并发需求时评估 PostgreSQL；ORM 不代表无需验证就能迁移。

T020 就保存任务和商品输入，刷新及服务重启后可以读取；T030 保存采集快照、证据索引和图片文件引用。修改所选规格或重新采集生成新版本，已有结论引用对应版本，防止价格和参数更新后结论错配。图片及会话文件存私有运行目录，用户输入数据不作为公开样例提交。

T035 已接入持久化检查点和单进程双工作线程执行器。LangGraph 保存图状态，`agent_runs` 保存需求、状态、工具输入输出、错误、耗时和返回的用量。模型请求最多 24 次、人工确认最多 3 次，单次执行片段最多 180 秒；等待人工输入不占工作线程。服务重启后将排队/运行记录标记中断，用户明确继续。创建幂等、同任务单活跃运行、失败重试、停止及任务删除检查点清理已实现；人工暂停后关闭再重开恢复有测试证据。分布式调度与外部浏览器动作的崩溃重放仍待后续建设。

首版先验证单机执行需求；消息中间件、分布式调度或更多服务根据真实并发、可靠性和部署需求引入。每项基础设施须有明确职责和验收方法。

## 5. 商品读取与证据

WXT content script 在淘宝、天猫和京东域名上提供 Shadow DOM 隔离、固定在视口右下方的页面悬浮助手；只在识别为商品详情页时允许添加。标题在面板预览，点击添加后扩展会读取共享 DOM/JSON-LD，并把当前 URL、清理后标题及版本化快照交给本机后台。后台校验来源、商品身份、证据引用与载荷后写入共享任务；工作台展示已识别字段和缺项。用户可更换目标或新建任务。浏览器管理页须授予匹配站点的内容脚本访问，并允许扩展访问 loopback 本机服务。任务删除使用 `DELETE /tasks/{task_id}`，后端通过 SQLAlchemy 级联删除该任务的商品链接；网页二次确认后删除并返回首页。

### T030 初始采集决策

研究默认由后台 Playwright 独立打开任务内商品页，有限等待和滚动后运行共享解析器；扩展可读取用户已打开的页面，作为主动加入和登录受阻后的接管通道。Chrome content script 默认运行在隔离世界：它可以读写共享 DOM，但不能直接访问商品站点 JavaScript 的全局变量。两条通道均读取可见商品 DOM、页面内 `application/ld+json` 等结构化脚本（`JSON.parse` 后校验）、当前可识别的选中规格。所有字段保留来源类型和原始文本。资料不足时返回部分结果或要求人工确认，不猜测 SKU、价格条件或图片覆盖。

自动规格核验使用目录观察与操作分离：`inspect_product_variants` 保存不可变目录快照，模型只返回组/选项 ID；`select_product_variant` 校验任务归属与目录、重新匹配目标、原生点击并等待选中/相关请求/价格状态稳定。结果进入快照的 `variant_catalog`、`variant_verification` 和选中属性；旧快照保持兼容。重开浏览器时按上次目录恢复其余选中分组，以支持分步选择。跨商品导航型选项当前不操作，价格记录只证明选中后的同页观察，不保证最终支付价。具体边界和执行证据见 [自动规格核验](AUTOMATIC_VARIANTS.md)。

默认不向 `MAIN` 世界注入采集代码，也不读取 Cookie、`localStorage`、完整页面源码或无关账号数据。只有真实页面样本证明某个关键字段无法从 DOM/结构化数据读取后，才单独评审更深的页面集成，并记录其额外权限、兼容性与安全代价；采集器不 `eval` 页面数据。平台页面内容、商家声明与 JSON-LD 均是不可信输入，只有用户确认或独立来源核对后才能标为已核实。

Playwright 现为后台生产采集器，同时用于固定样本回归。每次创建独立 context，不读取或复制现有 Chrome/Edge 配置。可由用户手动执行独立登录脚本，将认证状态原子保存到应用数据目录，后续后台复用；过期或验证时明确接管。Cookie 和浏览器状态不进入仓库或公开日志。具体网络限制、时限、幂等与私有状态撤销见 [后台采集说明](BACKGROUND_COLLECTION.md)。

每次采集追加不可变 `CaptureSnapshot`，保留 `item_id`、平台、采集时间、页面/规范链接、适配器及版本和整体状态。字段观察分别记录原文、可选规范值、证据引用和字段状态。规格至少保留用户当前选中的可见选项与其属性；价格以多条 `PriceObservation` 表示，分别记录金额、价格类型、数量/地区/运费/会员/券等条件，不能把划线价、起售价或优惠后估算混成一个价格。详情图记录顺序、可见描述、加载状态与私有资源引用；未滚动/未加载图计入缺失覆盖。每个字段的状态区分 `observed`、`user_confirmed`、`ambiguous`、`missing`、`blocked` 和 `not_applicable`。重采集或更换规格产生新快照，旧证据不覆盖。

各平台适配器提供页面读取、规格识别、参数提取、图片覆盖和失败分类；单位归一与金额计算为确定性代码。模型处理图片及解释差异时必须引用证据，不能把视觉推断作为已确认参数。页面状态、已选 SKU 与采集时间作为同一次快照保存。搜索结果只提供线索，候选详情和硬条件必须核实。

页面内容、搜索结果及图片均为不可信资料。后台校验工具名、参数和允许访问的目的地；不执行页面中的指令。身份、规格、价格或关键硬条件无法确认时，允许补查和人工介入，并明确说明结论的覆盖范围。

T030 持久化实现使用版本化 Pydantic 契约和 SQLite JSON 快照载荷；关系列保留商品、平台、适配器版本、采集/接收时间、状态与幂等键。`POST`/`GET /api/v1/tasks/{task_id}/items/{item_id}/captures` 追加和读取历史快照，不提供覆盖更新。写入校验任务内商品归属、页面与原链接的同平台商品 ID、证据引用、字段数量和 512 KiB 载荷上限；页面链接只保留商品标识，去掉跟踪查询参数。本机 Alembic 迁移已应用，Edge 扩展已调用此 API 并由工作台显示结果。首个天猫真实样本为部分采集：价格原文、主图引用和页面 SKU 标识已记录；品牌、规格、选中规格与详情图区域缺失。适配器版本 `0.1.1` 已构建到 Chrome/Edge，仍待重新加载扩展后在真实页面复验。详情图字节仍未上传或持久化；URL/元数据不等于已保存或分析了图片内容。

未知区分未采集、未提供、冲突和不适用。重复请求使用幂等标识控制；相同 URL 不代表相同 SKU，重复输入不能覆盖不同采集快照。类型检查与 JSON Schema 合法不证明商品事实真实，仍需字段校验和来源核对。

## 7. 首个产品流程与质量条件

T020 按推荐结构建立 React 网页、WXT 扩展、FastAPI API、数据库和迁移。网页创建任务并添加链接；扩展在淘宝、天猫、京东页面显示悬浮面板，用户选择/沿用目标任务后单击即可提交当前详情页；两入口访问同一后台任务。T030 点击后由内容脚本读取当前页面 DOM/JSON-LD，提交可识别字段、来源和覆盖状态，工作台显示快照及缺项。真实天猫样本已证明部分快照保存，不代表商品分析成功。用户可在任务详情删除整个任务；二次确认后，任务与所属商品链接一起删除。缺失任务名时，若已有页面标题则调用配置的 Chat Completions 兼容网关生成品类/用途级比较名称，不以单个商品命名，也不包含品牌、店铺、平台、型号或 SKU。名称只在创建任务时生成一次；之后新增、修改或移除商品不会自动改名，用户可以手动编辑任务名。标题生成只发送商品页标题，不发送 URL；仅粘贴链接的网页入口目前没有页面标题，须手动填写任务名。商品链接以短链接显示，可编辑标题、打开详情或移除，并对疑似购物车、订单和账号页提示核对。仅登记或部分采集阶段不伪造商品分析。

T020 检查正常提交、重复请求、非法 URL、任务不存在、任务删除级联、后台中断、刷新与服务重启；数据库记录不能丢失。Chrome、Edge 分别验证悬浮层、站点权限、任务选择和单击写入；页面有清楚的加载、成功、失败和重试反馈。质量验收与学习掌握分别记录。

T030 起使用人工核对过的真实商品样本，覆盖不同 SKU、优惠门槛、缺失参数和未加载图片。T040/T050 起检查证据引用、硬条件满足情况、错误恢复、暂停/继续、循环停止和确实有/无合格候选的路径。T060 汇总固定案例、性能与回归结果；任何比例和性能主张都需样本与真实测量。
