# 替代商品搜索与逐项核验

## 当前范围

2026-11-02 最新决定：用户确认京东专用及日常浏览器均受限，京东后台搜索/采集/独立登录默认暂停。工具直接返回 `jd_automation_disabled`，不访问平台，不把暂停当成无结果；后文京东单次成功记录为历史验收，不表示现可稳定使用。[访问决定与替代路线](JD_DATA_ACCESS.md)

2026-10-29 接入 `set_search_requirements → search_products → adopt_search_candidate`，候选加入现有任务后使用已有采集、规格核验和报告工具。模型决定查询、平台、候选与补查顺序；程序验证参数和证据。

在研究需求中说明“寻找其他品牌替代品”及硬条件即可。工作台显示提取出的硬条件、偏好、搜索范围、候选和核验结果。条件有误时可以停止后修改需求重新研究；Agent 提问时也可在回答中修正，再由模型更新条件。尚未提供运行中直接编辑条件表的交互。

搜索默认使用隔离 Chromium 和项目私有会话；显式开启 `SHOPPING_AGENT_BROWSER_CDP_ENABLED` 时优先连接用户启动并手动登录的专用浏览器，与详情采集使用同一配置。配置随搜索 worker 传递，不读取日常浏览器配置。连接失败时明确记录退回独立浏览器，不将登录失效或验证失败记成无候选。入口仍固定为淘宝搜索与京东搜索，不接受任意 URL、脚本或选择器。查询会发送给目标平台，返回文字会进入配置的模型上下文；详情图识别由候选详情采集的独立开关控制。

## 数据流与证据

1. 读取原商品证据，登记原商品 ID、编号硬条件与偏好。
2. 按平台和查询搜索当前第一页，最多记录五个商品线索；直接链接标为 `identity_source=direct_link`。新版京东没有直接链接的商品卡片，只有匹配 `.plugin_goodsCardWrapper[data-sku]` 或 `.gl-item[data-sku]`、可见且有合法数字 SKU 与标题时，才生成规范详情入口，标为 `sku_card` 并保留 `locator`。隐藏、无标题、无关节点或非法 SKU 不纳入。去除追踪参数并按商品身份去重；这些资料不直接成为商品事实引用。
3. 模型提交本次运行实际返回的搜索 ID 与候选 ID。后端验证归属，最多加入三个不同候选，任务仍最多二十件商品。不能由模型凭空生成候选 URL。
4. 候选加入与操作记录在同一事务提交；写入前锁定并核对运行状态。取消拒绝写入；同操作重放不重复加项。已保存搜索结果重放不重新访问网页；保存前崩溃可能重复只读访问，不承诺网络恰好一次。
5. 读取候选详情。报告为每个已加入候选逐项记录 `matched / unmatched / unknown`，不能省略失败候选。
6. 确认满足或不满足必须引用该候选本次已读的有效详情快照；品牌关系引用双方 `product.brand` 字段。旧快照、另一商品、搜索标题和访问受阻证据不能冒充当前详情证明。品牌别名和语义判断仍依赖模型，程序并非完整事实证明器。
7. 不同品牌且全部硬条件有证据满足才允许 `qualified`；明确不满足为 `rejected`，其他为 `needs_evidence`。没有合格候选时不能提交替代搜索成功的 `recommendation`。

原商品与候选共同进入确定性价格核算；价格更低本身不证明符合用途或全部硬条件。

## 边界与失败处理

- 每运行最多四次搜索、三个不同候选；每次搜索默认 55 秒，复用独立进程监督与取消回收。
- 加入搜索候选后，后台采集/目录读取和规格选择的上限各由三次扩展到六次；扩展接管仍最多三次。模型最多 24 次调用，单执行片段仍最多 180 秒。
- 只有页面明确表示没有结果才返回 `no_results`。登录/风控返回 `blocked`；空白、未加载、解析不支持或网络失败返回 `unavailable`，都不能等同于全平台没有商品。
- 只读取直接详情链接和已识别商品卡片的显式 SKU，不请求广告跟踪链接、不翻页、不自动处理登录或验证码。遇到受阻可换查询/平台，或结束为有明确限制的阶段性结果。
- 专用浏览器接管只操作本次新标签，使用页面级原生请求校验，不改变共享 context 的路由/默认超时，不关闭已有标签。结果的 `note` 标明实际通道。页面首批结果最长等待 20 秒，仍受整个浏览器动作期限限制，避免固定约 5 秒采样过早退出。
- 搜索登录/验证必须在同一专用浏览器手动完成，日常浏览器完成不代表后台已可访问。当前没有工作台专用搜索登录按钮；可将本次搜索链接复制到专用窗口，验证后再研究。不保证每个页面或后续会话都解除平台风控。

## 验证记录（2026-11-02）

- 本轮真实查询示例为“保温杯 500ml”：淘宝经专用浏览器返回五条直接链接；京东先受验证页拦截，用户在专用窗口手动验证后，新打开搜索页可用。补齐新版 SKU 卡片识别后京东返回五条 `sku_card` 线索，约 4.1 秒。这里只证明单查询的真实搜索，不证明替代品已合格或平台覆盖率。
- 淘宝实际分段链路 `search_products → adopt_search_candidate → collect_product_page` 在隔离库完成，候选详情为 `partial`，3 个字段记录、5 条可用证据；其中标题/店铺有观察，品牌字段为 `missing`，不能把字段存在记成品牌已读。未调用模型作资格结论。
- 京东真实搜索与候选写入已通过；详情访问单独记录：一个新版页面经 `.sku-title-text` 适配后取得标题，仍是 `partial`，品牌、规格、价格与详情图未获完整核验；另一候选的采集 worker 失败，未得到有效商品资料。不能把“有线索/已加入”记为品牌或硬条件已核验。
- 真实模型 + 真实京东搜索的边界回归：相同示例查询再次触发 `verification_required`，Agent 完成读取原资料、登记条件、搜索与两阶段报告，5 次模型调用、61.8 秒，以 `needs_evidence` 结束，未伪造候选或合格替代品。该案例验证受阻处理，不是成功完成品牌替代推荐。
- Windows 后端累计 236 项通过、1 项要求可见桌面而跳过；新增 11 项搜索接管检查覆盖真实 CDP、已有标签保留、延迟卡片、验证/无结果/不支持的区分、主文档跳转、取消、配置传递、连接失败回退，以及非法/隐藏/重复 SKU 卡片。新版京东标题另有浏览器回归。Ruff、前端类型、扩展通道 7 项及网页/Chrome/Edge/collector 构建通过，扩展与解析器版本为 `0.3.1`。

## 伴读与练习

关键代码为 `product_search.py`（浏览器读取）、`search_runtime.py`（持久化操作与引用约束）、`search_schemas.py`（输入和逐项结论）、`ResearchSearch.tsx`（范围与结果呈现）。

学习顺序：先解释“搜索线索与详情证据”的区别，再跟踪一次搜索 ID 如何变成任务商品 ID，最后观察检查点恢复为何不会重复加入候选。修改练习：在合成页面增加第四个不同候选，验证三候选边界；再把一个必需参数删除，确保它变成待核实而非自动通过。

失败案例：模型引用原商品证据证明候选满足条件，程序会拒绝报告并返回修正理由。查看真实合成探针的该次退回记录，解释引用“存在”与引用“属于正确商品和当前快照”的区别。
