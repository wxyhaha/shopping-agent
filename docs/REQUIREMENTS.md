## 首版的完整用户流程

1. 在本地网页粘贴链接，或在淘宝、京东页面通过扩展加入当前商品。
2. 记录具体选中规格、店铺和可见价格；规格不明确时展示待确认状态。
3. 输入或补充用途、商品预算、关注点与必须满足的条件。商品购买预算与项目开发费用是不同概念。
4. 读取页面文字、参数、详情图片，并记录来源、时间、缺失项和冲突。
5. 比较用户提供的商品；金额由代码按明确条件计算。
6. 提取替代品所需硬条件与偏好，允许用户查看和修改。
7. 在淘宝、京东寻找不同品牌候选，打开详情核实；记录差异与未知信息。
8. 展示候选、参数、价格条件、优缺点、推荐理由和证据；找不到合格候选时说明实际检索范围。
9. 对采集失败、登录失效、模型限流等保留明确错误和可恢复的任务状态。

第一阶段可以只完成上述流程的一部分作为开发反馈，但必须清楚标注未完成项；完整首版需要覆盖网页、扩展、两个平台和跨品牌检索闭环。

## 逻辑组件分工

| 组件 | 责任 |
| --- | --- |
| 本地网页 | 链接输入、需求与条件确认、任务进度、比较表、证据、历史结果 |
| 浏览器扩展 | 用户触发采集当前页面和选中规格、采集预览、提交到共享任务、打开网页结果 |
| 共享后台 | 数据校验、参数与单位整理、证据和持久化、价格计算、任务生命周期 |
| Agent 与浏览器工具 | 识别信息缺项、搜索候选、读取核实、决定补查或停止、形成有依据的建议 |
| DeepTutor 伴读 | 基于当前代码与执行记录教学、练习、理解检查和学习交接 |

自动搜索的实际执行工具尚未选定，不能仅依靠用户手动逐一添加商品来替代 R06。

## 数据和结论原则

- 同款比价需匹配品牌、型号、具体 SKU/配置、数量与售后条件。
- 替代商品比较需区分硬条件和可取舍偏好；相似标题、相同大类或低价格不足以证明等价。
- 通用商品信息加品类相关参数；单位、范围、数值口径和语义需归一，不能把所有品类塞入一张固定数码参数表。
- 价格区分标价、可确认价格、满足条件后的金额、未知金额；包含运费和实际适用条件，不把会员、补贴或凑单自动算作人人可用。
- 商家宣称、原厂资料、用户评价、独立测试、程序计算和模型推断分别标注；没有实测证据不生成可靠性结论。
- 每个关键事实与推荐依据能回到来源链接及原文、截图区域或其他证据记录；旧价格不得伪装成实时价格。
- 详情图、懒加载、登录、验证码与不可访问内容允许人工接管或补充；不得把空白读取当成完整阅读。
- 记录工具行为即可，不要求模型公开内部思维过程。

## 当前首版不包含的能力

以下为根据“购物辅助决策”目标拟定的首版边界，若需要扩展再讨论：

- 自动下单、付款、修改购物账号。
- 全网所有购物平台和所有商品的覆盖承诺。
- 没有数据来源的历史最低价或未验证的“全网最低价”保证。
- 多用户商业化运营、复杂权限系统与移动 App。
- 价格追踪和主动降价提醒作为后续候选，不挤占当前首版范围。
