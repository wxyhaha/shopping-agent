# 扩展读取当前商品页

## 本轮范围（2026-11-02）

用户选择继续验证浏览器扩展路线：正常浏览商品后，由扩展读取当前已加载资料，本机后台保存证据与研究结果。用户确认日常浏览器能显示淘宝/天猫参数和详情图；当前天猫页的浏览器观察也看到了对应区域。这只证明页面可访问，不等于扩展字段已采齐。

当前扩展实现版本为 `0.3.13`，没有新增权限，没有恢复京东访问。Agent 的默认后台采集策略尚未整体替换，自动搜索候选与浏览器端图片内容传输仍不属于本轮已完成能力。

## 浏览器端详情图识别补充（2026-11-04）

扩展 `0.3.13` 将商品基础采集与详情图文字读取合并为一次工具栏触发：在浮窗选择目标任务（也可创建新任务）后，点击一次工具栏图标，弹窗自动把读取交给浮窗。浮窗通过同一次滚动同时生成商品 DOM 快照和详情区截图，先保存基础快照，再将同一次读取取得的截图分批上传识别；无需先单独点“加入并采集”，也不再重复滚动。没找到可识别截图时仍保存基础快照并说明跳过 OCR。任一路径成功保存当前商品后，“加入并采集商品信息”改为“已加入当前任务”并禁用，避免误点造成新的重复快照；需要重读时点击工具栏图标。失败时可从弹窗重试；进度和取消由浮窗管理。取消时恢复到点击读取前的页面滚动位置，并在清理后再复核一次；页面已切换或标签页处于后台时不强制滚动。若直接点浮窗而浏览器尚未授予截图权限，仍需点击工具栏图标触发这次读取。`0.3.9` 修复了标签页 URL 暂不可读及滚动时 URL 片段变化可能导致的“商品页已切换”误报。截图使用既有 `activeTab` 临时授权，只处理淘宝/天猫详情区中当前可见且已加载的 `<img>`；整次读取没有总段数上限，截图之间至少间隔 650ms。每次 API 请求最多 16 段，串行上传并等待前批识别完成后继续；单次请求体和单图大小保护仍生效。图片在浏览器内裁剪和压缩后发送到本机 API，由已配置的视觉模型异步识别。截图像素只在请求与后台任务内存中短暂存在，不写入本项目数据库或文件；数据库保存识别文字、全部截图段来源和商品页定位。此路径不请求商品图片 CDN，也不新增扩展权限。

用户在真实使用 `0.3.12` 时发现：工具栏流程已经保存商品，但“加入并采集商品信息”按钮仍保持可用，再点会重复滚动并保存第二个快照。`0.3.13` 在成功保存后把该按钮更新为已完成并禁用，避免紧接着误触。`0.3.13` 的 `npm run typecheck`、Chrome/Edge 构建及 `git diff --check` 均通过，构建产物权限仍为 `activeTab`、`storage`、`alarms`；用户随后确认真实 Edge 修复验收通过。

### 单次合并采集的实页验收（2026-11-04）

用户确认 `0.3.13` 在真实 Edge 商品页上的重复采集问题已解决。只读核对本机 API：最新任务包含 4 个商品项，最新商品项仅有 1 份快照；该快照状态为 `partial`、`detail_enrichment=done`，包含 98 条 `extension_screenshot` 证据。164 条非空 `detail_images.*` 文字观察值均为 `ambiguous`，引用 49 个不同截图证据。此结果支持一次工具栏流程保存一份基础快照并完成 OCR，不证明详情页完整，也不把商家图文升级为已核实规格。

Agent 侧代码审查确认，`read_product_evidence` 会把详情图参数/购买条件和对应引用数组交给模型；系统指令要求将其标为商家表述，不能视为已核实规格。下一步需要真实研究报告验收该表达与引用边界；尚未对这批用户商品启动新的 Agent 研究。

### 早期实页截图验收（2026-11-04，0.3.13 前）

用户在已打开的天猫商品页从工具栏启动读取。基础快照 `860d3b29-7bb4-4213-a2ba-2c5174c6b08a` 新增 56 个截图证据位置，编号 1–56，按 4 批处理，批量为 16、16、16、8；`detail_enrichment` 最终为 `done`。后台写入 165 条 `detail_images.*` 文字观察值，原文均非空、状态均为 `ambiguous`，并引用截图证据；不将商家详情图文字规范化为已核实规格。快照仍为 `partial`。

API 返回的快照证据只含来源、文字摘录和定位，没有 `image_base64` 或图片内容字段；实现将原图字节用于内存中的视觉识别，不写入数据库或文件。该样本证明超过 16 段的连续上传与识别已在一个真实天猫页面跑通，不证明页面内容完整。读取前的精确滚动值没有记录；读取后观察到页面位于详情区，故滚动恢复尚未判定通过。该验收早于浮窗整合，不能证明新浮窗的启动与取消交互已通过实页验收。

### 详情图截止位置与无总段数上限（0.3.7）

每轮检查会读取已识别详情容器内有布局的 `<img>` 页面坐标，计算最靠下图片的底边；图片延迟加入或位置改变时会更新目标。正常完成必须同时满足：已识别容器底部到达视口、最靠下图片底边到达视口、图片列表/位置/加载状态稳定至少 1 秒，且没有仍在加载的已发现图片。到达容器末端但没有可定位图片时返回 `cutoff_not_found`，不冒充成功。本采集路径没有总滚动次数、总时长或截图段数上限；用户取消、页面变化或用户接管仍会中止。CSS 背景图、Canvas、iframe/未识别容器、折叠或尚未加入 DOM 的内容不能由 `<img>` 坐标证明覆盖完整。

### 使用步骤

1. 构建后重新加载 `frontend/.output/edge-mv3` 或 `frontend/.output/chrome-mv3`，刷新商品页，确认悬浮面板显示 `v0.3.13`。
2. 在淘宝/天猫商品页的右下角浮窗选择目标任务；也可以保留“创建一个新比较任务”。不需要先点“加入并采集”。
3. 点击一次工具栏 Shopping Agent 图标。弹窗会自动启动合并流程：一次滚动读取商品 DOM 并截图，再保存快照和识别详情图。查看弹窗提示后可关闭弹窗，保持商品页可见；状态、进度和“取消本次读取”都在右下角浮窗管理。若启动失败，可在弹窗中点重试。
4. 读取过程中，浮窗展示同次滚动、基础快照保存、当前批次上传与识别等待状态；点“取消本次读取”会停止尚未完成的页面读取和后续截图批次，并恢复到点击读取前的滚动位置。基础快照一旦保存会保留；已确认接收的批次及后台识别也会保留；取消时正在发送的一批可能已被接收，浮窗会标为状态未知。
5. 浮窗提示完成后，刷新工作台的商品采集信息查看快照和详情图文字。视觉识别在后台异步运行；最后一批可能还需等待。`SHOPPING_AGENT_DETAIL_VISION_ENABLED` 必须启用且本机服务可用，图片会发给项目配置的视觉模型服务。

普通预览、普通采集和工具栏截图读取均没有总滚动次数或固定时长上限，持续到已识别的详情末端；截图读取也没有总段数上限。截图按每批最多 16 段提交，单次请求体不超过 12 MiB，前一批识别完成后才发送下一批；证据列表没有总段数上限。Agent 被动桥接读取不滚动。仅处理被识别详情容器内已加载的 `<img>`。CSS 背景图、Canvas、未加载或折叠的内容仍可能缺失。扩展会先将本轮截图暂存在内存，再逐批上传，极长页面仍受浏览器内存和消息容量影响。即使追踪到容器和最末图片位置，覆盖状态仍保持不完整，不把截图数量写成整页覆盖。相同截图批次重试不会重复调用视觉模型。京东仍暂停，Agent 默认采集通道也未切换。

`0.3.11` 的类型检查、Chrome/Edge 构建和 `git diff --check` 均通过；两个构建产物版本为 `0.3.11`，权限未变，用户确认取消后滚动恢复正常。历史天猫快照 `860d3b29-7bb4-4213-a2ba-2c5174c6b08a` 有 88 条截图证据，分 6 批（5 批 16 段、1 批 8 段），`detail_enrichment=done`，状态仍为 `partial`；165 条非空详情图文字均为 `ambiguous`，引用 70 条截图证据。用户报告另一商品已按旧两步流程完成基础采集与详情读取；API 未在本轮复核该结果，新版本的一趟流程仍待验收。API 不记录取消事件或预期段数，不能单靠数据库判定未开始批次数。`npm run test:extension` 的 15 项结果来自先前 `0.3.7` 检查，不能作为新行为验收。OpenAPI 导出、typegen 与后端 Ruff 检查通过于 `0.3.6`。后台曾确认 readiness 正常，数据库有 3 条旧 pending 快照，新服务不会自动恢复它们。

2026-11-04 早先的天猫快照 `59490890-b220-47ee-aed2-9bf6d4cdf0c7` 显示普通采集在滚动 24 次后被旧上限截断，已定位 28 张图片，最下方图片底边仍约 40651px；该快照没有工具栏截图来源。原因是普通预览与保存调用没有启用 `untilCutoff`，仅截图入口启用了它。`0.3.7` 已为两个普通交互入口补上该选项；其后用户确认普通采集截止正常，并完成 56 段工具栏截图样本，具体边界见本节实页验收。

## 使用步骤

1. 构建入口沿用 README；Edge 加载 `frontend/.output/edge-mv3`，Chrome 加载 `frontend/.output/chrome-mv3`。已安装的开发扩展需重新加载，再刷新商品页，确认面板显示 `v0.3.13`。
2. 打开可以正常显示资料的淘宝/天猫商品，手动选好规格，等待价格更新。“读取预览”无需后台，仅在本地读取与显示，不提交快照。
3. 如需只保存基础快照，在悬浮助手选择任务并点击“加入并采集商品信息”；这条普通采集路径不负责详情图 OCR。需要同次滚动保存商品信息并识别详情图时，按上方工具栏步骤启动完整读取。
4. 详情图读取过程中，“取消本次读取”在浮窗详情按钮下方；取消后未开始的批次停止，已确认接收的截图会保留，正在发送的一批状态可能未知。基础采集开始上传后仍会隐藏取消按钮，因为服务端可能已经保存。
5. 读取后查看预览和工作台覆盖记录。图片链接不等于图片文字已识别，金额存在不等于价格条件已经可比。

本轮不能要求用户为京东重新登录或验证。若页面本身受限，扩展不能补出平台没有展示的资料。

## 数据流和边界

普通基础采集：点击浮窗操作 → 锁定按钮与任务选择 → 校验页面及选中规格 → 展开可识别参数 → 滚动到已识别末端并等待 → 恢复原滚动位置 → 核对规格/价格 → 提交共享快照 API。完整详情读取：点击工具栏图标临时授权 → 同一趟滚动中读取 DOM 快照并截取详情区 → 保存快照 → 逐批上传同次滚动截图并等待异步识别 → 工作台与 Agent 读取相同来源记录。进度、取消和状态均由右下角浮窗管理。

- 普通预览、普通采集和工具栏截图流程都滚动到识别的详情末端；用户操作、取消、页面变化或切到后台会停止。Agent 被动桥接仍只读当前页，不滚动。
- 已识别详情容器末端和最靠下图片底边均到达、已发现图片在 1 秒观察期内稳定，只能说明本次有限观察稳定。覆盖记录 `page.detail_preparation` 始终为 `ambiguous`，快照不因此标记完整。
- 切换页面、选中规格变化、取消、前台读取切到后台或用户操作会中止。检测到用户操作后不强行恢复滚动；正常完成、仍在原可见页面时才恢复。
- 仅点击可识别的参数标签，排除链接、表单、禁用按钮和纯标题；不选择 SKU、不操作购买按钮。
- Agent 对已打开标签的补采集本轮采用被动读取：不自动滚动、不展开页面，覆盖说明明确本次只读取当前已加载内容。
- 图片来源沿用本次最多 40 张的总量边界；符合规则的图片超过剩余额度时，`images.gallery` 或 `images.detail` 明确标记歧义与截断，不把截断写成完整。
- 新版天猫两种参数卡片分别读取标签与值，避免相反顺序导致漏读；平台标注为 AI 提取的参数保留 `ambiguous`。参数汇总最多引用 20 条，逐项参数和引用仍保留，避免真实多参数商品被接口拒收。
- 普通扩展快照仍提交允许来源的图片 URL 与尺寸，旧的后台视觉通道可能按配置下载图片；新增的工具栏详情图路径使用浏览器截图像素，后台不再请求这些商品图片 URL。两条能力不能混称为所有采集路径都已不访问商品图片 CDN。
- 截图只截取识别到的详情容器中可见 `<img>` 的外接区域，再由浏览器 Canvas 裁剪和压缩；不会保存完整页面截图。对页面中的个人区域和非图片文字，本功能不做视觉补充。
- `0.3.7` 普通交互采集的截止行为已获用户实页确认；工具栏截图超过 16 段的上传与识别已在单个天猫样本验收。`0.3.11` 取消后的滚动恢复已获用户确认；多商品稳定性和已接收批次边界仍待扩大验收。没有更改 Agent 默认优先使用后台采集的策略，也没有实现扩展搜索页采集。

## 学习交接

关键概念：内容脚本、service worker 与后台是三个执行位置；页面加载完成不代表详情懒加载完成；取消必须阻止提交，重复点击与响应丢失要分别处理；有限等待的观察结果不能证明完整性。

可修改练习：用受控长页面观察普通采集与工具栏截图如何到达容器及末图边界，再用取消和页面操作验证中止。失败案例：读取时改变选中规格，旧价格与新规格不能混成一次快照。学习练习留到稳定版本后，不阻塞本轮开发。
