# 扩展读取当前商品页

## 本轮范围（2026-11-02）

用户选择继续验证浏览器扩展路线：正常浏览商品后，由扩展读取当前已加载资料，本机后台保存证据与研究结果。用户确认日常浏览器能显示淘宝/天猫参数和详情图；当前天猫页的浏览器观察也看到了对应区域。这只证明页面可访问，不等于扩展字段已采齐。

本轮扩展与共享解析器版本为 `0.3.3`，没有新增权限，没有恢复京东访问。当前首先验证手动点击读取；Agent 的默认后台采集策略尚未整体替换，自动搜索候选与浏览器端图片内容传输仍不属于本轮已完成能力。

## 浏览器端详情图识别补充（2026-11-04）

扩展 `0.3.7` 保留 `0.3.4` 的手动截图识别入口：用户点击扩展工具栏图标，在弹出面板点“读取详情图文字”。扩展复用既有 `activeTab` 临时授权，只截图淘宝/天猫详情区中当前可见且已加载的 `<img>` 区域；整次采集没有总段数上限，截图之间至少间隔 650ms。每次 API 请求最多 16 段，扩展串行上传并等待前批识别完成后继续；单次请求体和单图大小保护仍生效。图片在浏览器内裁剪和压缩后发送到本机 API，由已配置的视觉模型异步识别。截图像素只在请求与后台任务内存中短暂存在，不写入本项目数据库或文件；数据库保存识别文字、全部截图段来源和商品页定位。此路径不请求商品图片 CDN，也不新增扩展权限。

### 详情图截止位置与无总段数上限（0.3.7）

每轮检查会读取已识别详情容器内有布局的 `<img>` 页面坐标，计算最靠下图片的底边；图片延迟加入或位置改变时会更新目标。正常完成必须同时满足：已识别容器底部到达视口、最靠下图片底边到达视口、图片列表/位置/加载状态稳定至少 1 秒，且没有仍在加载的已发现图片。到达容器末端但没有可定位图片时返回 `cutoff_not_found`，不冒充成功。本采集路径没有总滚动次数、总时长或截图段数上限；用户取消、页面变化或用户接管仍会中止。CSS 背景图、Canvas、iframe/未识别容器、折叠或尚未加入 DOM 的内容不能由 `<img>` 坐标证明覆盖完整。

### 使用步骤

1. 构建后重新加载 `frontend/.output/edge-mv3` 或 `frontend/.output/chrome-mv3`，确认悬浮面板显示 `v0.3.7`。
2. 在淘宝/天猫商品页，先用悬浮助手把商品加入任务并保存一次基础快照；在浏览器工具栏点击 Shopping Agent 图标。
3. 点“读取详情图文字”，等待滚动到已识别末端并完成截图。保持该标签页可见；操作页面、切换标签或点悬浮助手中的“取消本次读取”会停止读取。
4. 弹出面板提示截图已提交后，刷新工作台的商品采集信息查看新字段。视觉识别在后台异步运行，可能需要等待。
5. `SHOPPING_AGENT_DETAIL_VISION_ENABLED` 必须启用且本机服务可用；图片会发给项目配置的视觉模型服务。关闭该开关时，接口会明确拒绝处理。

普通预览、普通采集和工具栏截图读取均没有总滚动次数或固定时长上限，持续到已识别的详情末端；截图读取也没有总段数上限。截图按每批最多 16 段提交，单次请求体不超过 12 MiB，前一批识别完成后才发送下一批；证据列表没有总段数上限。Agent 被动桥接读取不滚动。仅处理被识别详情容器内已加载的 `<img>`。CSS 背景图、Canvas、未加载或折叠的内容仍可能缺失。扩展会先将本轮截图暂存在内存，再逐批上传，极长页面仍受浏览器内存和消息容量影响。即使追踪到容器和最末图片位置，覆盖状态仍保持不完整，不把截图数量写成整页覆盖。相同截图批次重试不会重复调用视觉模型。京东仍暂停，Agent 默认采集通道也未切换。

`0.3.7` 的类型检查和 Chrome/Edge 构建通过；OpenAPI 导出、typegen 与后端 Ruff 检查通过于 `0.3.6`。后台已启动，运行时 OpenAPI 确认每批最多 16 段且没有快照总数上限；用户已确认普通交互采集到达截止位置，工具栏截图超过 16 段后的连续上传和识别尚未验收。数据库保留 3 条旧的 `detail_enrichment=pending` 记录，新服务不会自动恢复它们。

2026-11-04 最新天猫快照 `59490890-b220-47ee-aed2-9bf6d4cdf0c7` 显示普通采集在滚动 24 次后被旧上限截断，已定位 28 张图片，最下方图片底边仍约 40651px；快照里没有工具栏截图来源。原因是普通预览与保存调用没有启用 `untilCutoff`，仅截图入口启用了它。`0.3.7` 已为两个普通交互入口补上该选项；需要重载扩展后再验收。

## 使用步骤

1. 构建入口沿用 README；Edge 加载 `frontend/.output/edge-mv3`，Chrome 加载 `frontend/.output/chrome-mv3`。已安装的开发扩展需重新加载，再刷新商品页，确认面板显示 `v0.3.7`。
2. 打开可以正常显示资料的淘宝/天猫商品，手动选好规格，等待价格更新。“读取预览”无需后台，仅在本地读取与显示，不提交快照。
3. 在悬浮助手中选择任务，点击加入并采集。读取时保持此页在前台；扩展尝试展开参数，并滚动到识别出的详情末端，展示进度。
4. 需要中止时点击“取消本次读取”。滚动、触摸或操作商品页面也会中止本次读取；不会保存本轮快照。上传开始后隐藏取消按钮，因为服务端可能已经保存。
5. 读取后查看预览和工作台覆盖记录。图片链接不等于图片文字已识别，金额存在不等于价格条件已经可比。

本轮不能要求用户为京东重新登录或验证。若页面本身受限，扩展不能补出平台没有展示的资料。

## 数据流和边界

手动点击 → 立即锁定按钮与任务选择 → 校验页面及选中规格 → 展开可识别参数按钮 → 滚动到已识别末端并等待 → 恢复原滚动位置 → 间隔 500ms 两次核对规格/价格 → 提交共享快照 API → 工作台与 Agent 读取相同来源记录。

- 普通预览、普通采集和工具栏截图流程都滚动到识别的详情末端；用户操作、取消、页面变化或切到后台会停止。Agent 被动桥接仍只读当前页，不滚动。
- 已识别详情容器末端和最靠下图片底边均到达、已发现图片在 1 秒观察期内稳定，只能说明本次有限观察稳定。覆盖记录 `page.detail_preparation` 始终为 `ambiguous`，快照不因此标记完整。
- 切换页面、选中规格变化、取消、前台读取切到后台或用户操作会中止。检测到用户操作后不强行恢复滚动；正常完成、仍在原可见页面时才恢复。
- 仅点击可识别的参数标签，排除链接、表单、禁用按钮和纯标题；不选择 SKU、不操作购买按钮。
- Agent 对已打开标签的补采集本轮采用被动读取：不自动滚动、不展开页面，覆盖说明明确本次只读取当前已加载内容。
- 图片来源沿用本次最多 40 张的总量边界；符合规则的图片超过剩余额度时，`images.gallery` 或 `images.detail` 明确标记歧义与截断，不把截断写成完整。
- 新版天猫两种参数卡片分别读取标签与值，避免相反顺序导致漏读；平台标注为 AI 提取的参数保留 `ambiguous`。参数汇总最多引用 20 条，逐项参数和引用仍保留，避免真实多参数商品被接口拒收。
- 普通扩展快照仍提交允许来源的图片 URL 与尺寸，旧的后台视觉通道可能按配置下载图片；新增的工具栏详情图路径使用浏览器截图像素，后台不再请求这些商品图片 URL。两条能力不能混称为所有采集路径都已不访问商品图片 CDN。
- 截图只截取识别到的详情容器中可见 `<img>` 的外接区域，再由浏览器 Canvas 裁剪和压缩；不会保存完整页面截图。对页面中的个人区域和非图片文字，本功能不做视觉补充。
- `0.3.7` 普通交互采集的截止行为已获用户实页确认；工具栏截图的超过 16 段上传、识别结果及取消操作仍待人工验收。没有更改 Agent 默认优先使用后台采集的策略，也没有实现扩展搜索页采集。

## 学习交接

关键概念：内容脚本、service worker 与后台是三个执行位置；页面加载完成不代表详情懒加载完成；取消必须阻止提交，重复点击与响应丢失要分别处理；有限等待的观察结果不能证明完整性。

可修改练习：用受控长页面观察普通采集与工具栏截图如何到达容器及末图边界，再用取消和页面操作验证中止。失败案例：读取时改变选中规格，旧价格与新规格不能混成一次快照。学习练习留到稳定版本后，不阻塞本轮开发。
